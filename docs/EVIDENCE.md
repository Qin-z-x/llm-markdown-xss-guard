## Scope and honesty statement

`mdxss-guard` is a defensive detection and sanitization tool plus a local demonstration. It does not disclose a new vulnerability, does not claim a new CVE and does not promise that a given chat UI is safe: XSS in rendered Markdown and permissive HTML sanitizers are long-standing public classes of bugs. The injected payload used in the demo only writes a marker into the page DOM (no cookie access, no network request) and the cleaned page does not execute it.

## Limitations

- Detection is heuristic and renderer-dependent: a UI that never renders raw HTML has a much smaller
  exposure, and a different Markdown renderer may allow constructs this tool does not model.
- Mutation-XSS and DOM-clobbering gadgets are out of scope; the sanitizer works on the HTML/Markdown
  text, not on a live DOM.
- The allowlist is intentionally strict: benign tags outside it are escaped (visible as text),
  which is a usability trade-off documented in docs/THREAT_MODEL.md.
- This is a defence-in-depth layer, not a browser sandbox. Pair it with a Content-Security-Policy
  and a battle-tested DOM sanitizer in the rendering layer.
